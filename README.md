# Две лабораторные работы по C++

Готовые консольные программы для C++17. ЛР 1 реализует AVL-дерево и множество, ЛР 2 — разреженный вектор с двумя вариантами поиска. Код дерева используется в обеих работах.

Расчёт рейтинга объёма: **ЛР 1 — 28 при минимуме 25; ЛР 2 — 57 при минимуме 55**. Рейтинг выбранных пунктов и итоговая оценка за защиту — разные величины. Подробный расчёт приведён в `lab1/TZ.md` и `lab2/TZ.md`.

## Запуск в VS Code на этом компьютере

1. Открой **всю эту папку** через **File → Open Folder**. Не открывай отдельно только `main.cpp`.
2. Нажми **Ctrl+Shift+P**, введи **Tasks: Run Task**.
3. Выбери **Run lab 1** или **Run lab 2**. Программа соберётся и запустится во встроенном терминале.
4. Вводи номер пункта меню и нажимай Enter. Для окончания выбери `0`.

Компилятор уже найден: `C:\Program Files\CodeBlocks\MinGW\bin\g++.exe` (GCC 14.2.0). Скрипт сборки использует его автоматически, если `g++` отсутствует в PATH. Консоль работает в UTF-8. Дробные числа вводятся **через точку**.

Другие задачи VS Code:

| Задача | Результат |
|---|---|
| Build all / Ctrl+Shift+B | Собрать все программы в `build/` |
| Test all | Собрать и запустить тесты обеих лабораторных |
| Benchmark | Выполнить замеры, сохранить CSV и построить графики |
| Build debug | Собрать с отладочной информацией |

Для отладки: поставь точку останова, открой Run and Debug, выбери **Debug lab 1** или **Debug lab 2**, нажми F5. Конфигурация использует уже установленный GDB из Code::Blocks.

Кнопка Code Runner «Run Code» не нужна: для этой папки подготовлены задачи сборки.

## Запуск из PowerShell

Открой терминал в этой папке:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Action lab1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Action lab2
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Action test
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Action benchmark
```

После сборки можно запускать без повторной компиляции:

```powershell
.\build\lab1.exe
.\build\lab2.exe
```

Программы собраны со статическими библиотеками GCC: добавлять DLL в папку не требуется. Исходники и настройки сборки являются основными материалами для сдачи; `.exe` можно пересобрать.

## Что попробовать в ЛР 1

1. Пункт `1`: введи `4 2 6 1 3 5 7`.
2. Пункт `5`: посмотри шесть обходов и высоту. Для этого примера высота равна 3.
3. Пункт `6`: увидишь преобразование `x/2`, фильтр положительных чисел и сумму `28`.
4. Пункт `7`, корень `2`: получишь `( 2 ( 1 # # ) ( 3 # # ) )`.
5. Пункт `8`: вставь эту строку — программа сообщит, что поддерево входит.
6. Пункт `9`: скопируй сериализацию; пункт `10` позволяет восстановить дерево из неё.
7. Пункт `12`: введи множества A = `1 2 3`, B = `3 4`. Объединение — `1 2 3 4`, пересечение — `3`, разность A−B — `1 2`.

Дерево хранит уникальные ключи. Повторная вставка ничего не меняет. `map` создаёт новое дерево; если разные исходные значения дали одинаковый результат, он хранится один раз. Пункты демонстрации `map/where/reduce` выводят результат, сохраняя исходную коллекцию.

Сериализация использует фиксированный обход КЛП: `( значение левое_поддерево правое_поддерево )`; `#` обозначает пустое поддерево. Строки заключаются в кавычки. Пример лежит в `examples/tree.txt`.

## Что попробовать в ЛР 2

1. Пункт `10`: путь `examples/vector.txt`, структура `1` (AVL).
2. Пункт `4`: размерность 12; ненулевые элементы: `[0]=2.5`, `[4]=-3`, `[11]=7`.
3. Пункт `3`, индекс `1`: ответ `0`; индекс `11`: ответ `7`.
4. Пункт `2`, индекс `4`, значение `0`: узел удалится из хранилища.
5. Пункт `5`, структура `2`: те же данные будут перенесены в отсортированный массив.
6. Пункт `12`: сравни поиск одного индекса обоими способами.
7. Пункт `9`: сохрани в `vector.txt`, затем загрузи через пункт `10`.

Индексы начинаются с нуля. Размерность и число хранимых элементов — разные величины: у вектора размерности миллиард может быть всего три ненулевых элемента. Сложение и умножение выводят новый вектор; исходный сохраняется.

## Замеры и графики

Замеры выполняются в Release (`-O2`). ЛР 1: 10 000, 100 000 и 1 000 000 узлов; вставка, поиск и удаление. ЛР 2: 1 000, 5 000 и 20 000 ненулевых элементов; отдельно построение и 100 000 запросов, среди которых есть успешные и неуспешные. В обеих работах проверяются возрастающий, убывающий и случайный порядки вставки. Для каждого случая выполняются три повтора; на графике показана медиана.

Графики: `results/lab1_performance.png`, `results/lab2_performance.png`; рядом — масштабируемые SVG. CSV содержат все повторы, включая контрольную сумму для проверки результатов. Исходные данные генерируются с фиксированным seed, одинаковым для сравниваемых алгоритмов.

Можно изменить размеры после сборки:

```powershell
.\build\benchmark.exe --tree-max 1000000 --sparse-max 20000 --repeats 3 --output results
```

Для дерева допустим предел до 100 000 000, но проведённые измерения ограничены 1 000 000 узлов — это нижняя граница «очень больших» объёмов из ТЗ. При выборе 100 миллионов потребуется несколько гигабайт памяти. Для массива вставка в обратном порядке имеет квадратичное суммарное время; потому размер второй серии меньше.

Графики строит `scripts/plot.py` с matplotlib. На этом компьютере задача Benchmark находит Python в среде Codex, а matplotlib установлен локально в `.plot-deps`. На другом компьютере можно установить matplotlib для своего Python и выполнить `python scripts/plot.py`. Каталог `.plot-deps` содержит библиотеки для Windows и Python 3.12; при переносе на другую платформу или версию Python его следует исключить. Сами программы и CSV-замеры от Python не зависят.

## Переносимая сборка через CMake

```text
cmake -S . -B build-cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build-cmake --config Release
ctest --test-dir build-cmake -C Release --output-on-failure
```

Нужен компилятор с C++17. Способ с CMake добавлен для переноса проекта; основная проверенная сборка на этом компьютере — через `scripts/build.ps1`.
